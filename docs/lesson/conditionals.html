Conditionals

A script that does the same thing no matter what is only half useful. Usually you want it to check something first: does the input file actually exist, did the previous step work, is this sample already done.

That is what if is for:

if [ -f reads.fastq ]
then
    echo "found it"
fi

Read it as: if this test passes, run the commands between then and fi. fi is if backwards, which is the shell's idea of a joke, and it closes the block the way done closes a loop.

You will also see it written on one line, which is what you get inside scripts most often. The semicolons stand in for the line breaks:

if [ -f reads.fastq ]; then echo "found it"; fi

The square brackets are a command. This is the part that makes everything else make sense. [ is not punctuation, it is a program, another name for test. It runs, it looks at what you gave it, and it exits 0 if the condition holds and non-zero if it does not. if then branches on that exit code, exactly the one from the previous lesson.

Two consequences follow immediately, and between them they account for most of the errors beginners hit:

The spaces are compulsory. Since [ is a command name, it needs a space after it, the same as any other command. And ] is an argument, so it needs a space before it. Writing [-f reads.fastq] gets you "command not found", because you have asked the shell to run a program called [-f.

Anything can be the condition, not just brackets. if will branch on any command's exit code:

if grep -q "chr1" variants.vcf
then
    echo "chromosome 1 is in there"
fi

No brackets at all. grep -q searches quietly and exits 0 if it found something, and that is all if needs.

The tests you will actually use. For files:

  • -f file - exists and is a regular file
  • -d file - exists and is a directory
  • -e file - exists, whatever kind of thing it is
  • -s file - exists and is not empty, which is the one you want after a download

For numbers, spelled out rather than symbols:

  • -eq equal, -ne not equal
  • -lt less than, -le less than or equal
  • -gt greater than, -ge greater than or equal

For text, using the symbols instead:

  • = equal, != not equal
  • -z string - the string is empty
  • -n string - the string is not empty

Note that numbers use -lt while text uses =. Mixing them up is a rite of passage. [ 10 -gt 9 ] is true, while [ "10" > "9" ] compares them as text and is false, because "1" sorts before "9".

Reverse a test with !, which is much more useful than testing the positive case, because most checks in scripts are "stop if something is wrong":

if [ ! -f "$1" ]
then
    echo "no such file: $1"
    exit 1
fi

That is the guard from the first script lesson, and now you can read every piece of it: if not a regular file named whatever was passed as the first argument, complain and exit with a failure code.

Quote your variables in tests. If $1 is empty and unquoted, the shell removes it entirely and test sees [ ! -f ], which is a different expression and behaves oddly rather than failing cleanly. "$1" with quotes stays one empty argument and the test does what you meant.

else and elif do what you would expect:

if [ -s results.txt ]
then
    echo "we have results"
elif [ -f results.txt ]
then
    echo "the file is there but it is empty"
else
    echo "nothing ran yet"
fi

One last thing you will see in other people's scripts. Bash also has [[ ]], a double-bracket version with extra features and fewer traps around quoting. It works well and it is what many people use, but it is a bash extension rather than something every shell has. Single brackets work everywhere, so that is what this course uses.

Exercise

  1. Write a script that takes a filename and prints whether it exists, using -f.
  2. Add an else branch for the missing case, and make the missing case exit 1.
  3. Run it on a real file and a made-up one, checking echo $? after each.
  4. Deliberately write [-f file] with no spaces and read the error you get.
